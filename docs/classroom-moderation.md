# Classroom microphone control and administration attendance

Students join with camera/video publishing allowed and microphone/screen-share audio publishing blocked. Their application-issued join tokens remain blocked even if they previously received permission. The server applies the current session's permission to a connected participant; the student explicitly enables their own microphone afterward. The teacher never remotely unmutes a student.

The teacher opens **مايكات الطلاب** in the classroom, grants/revokes a named student's permission, or locks everyone. The server validates the owning teacher, active student enrollment, live session ID and microphone version. LiveKit source permissions enforce the restriction, and already published audio tracks are muted. Only student-role users are updated; parent and hidden administration observers retain subscribe-only permissions. The camera publishing source remains allowed. Permission records are scoped to a session and cleared on completion.

Provider changes cannot share a database transaction. The desired permission is saved first; application to LiveKit reads the latest committed state under the course lock. Provider failures return an explicit non-success response. The dialog displays pending confirmation and provides a retry that preserves the intended permission. It never silently opens a student's microphone while retrying a failed mute. Concurrent changes return a conflict if the permission version changed during application.

Administration opens **تفاصيل الحصة والحضور** beside each class in a course. It displays the scheduled date, actual session start/end, assigned teacher, recorded student roster, first joins and connection visits. Starting a session is distinct from entering its LiveKit room. Parents and students cannot access the administration details endpoint.

Attendance comes from signed LiveKit webhooks and server-authenticated participant snapshots, not a browser's claim that it clicked Join. Connected teacher/student clients periodically confirm their connection, and administration refreshes every 15 seconds while visible. This also provides attendance if provider webhooks have not been configured. Participant SIDs distinguish separate connections, so delayed exits cannot overwrite a later rejoin. Parent and administration observers do not receive attendance or XP.

Exit sources distinguish an exact provider event (`WEBHOOK`), observed absence from a provider snapshot (`OBSERVED`, approximate), and closure at session completion (`SESSION_END`). Provider outages produce an unknown current-presence state rather than marking users absent. Saved history remains available after enrollment cancellation. Historical classes may have attendance without connection visits or teacher arrival records; those times are never fabricated.

Validation includes API ownership/role boundaries, locked join/rejoin tokens, source restrictions, active-track muting, pending provider failure recovery, duplicate visits, delayed exits, outage rendering and historical roster retention. Browser tests cover the real JavaScript SDK permission event, rejection of forged data-message permission, microphone shutdown, dialog retry behavior and responsive administration pages. A real WebRTC classroom test is included for environments that can run a local LiveKit server; this workspace currently blocks the kernel netlink calls needed to start that server.
